# RoomFlow 首版需求基线

更新时间：2026-09-14。来源：桌面交接文档与本次用户确认。此处后续明确回答覆盖交接文档早期建议；未决项不得当作已批准规则。

## 定位与交付

学习、面试演示项目，预计同时使用不超过两人。48小时为期望，不是严格截止时间；AI预算无明确上限。Codex负责准备，Devin Desktop在Windows本机负责开发。目录为桌面RoomFlow，公开仓库 https://github.com/niuyeyeplus/RoomFlow.git。

## 业务与权限

- 实体会议室是有限资源，初始化三个房间，ADMIN可动态创建、修改、启停和删除。所有用户可发起会议，选择已有房间及空闲时段。
- 发起人复制普通会议详情链接自行发群。用户登录后直接报名同一会议，不创建另一条房间预约。不做在线音视频、短链接服务或自动发群消息。
- 所有登录用户可查看会议与预约者、报名。发起人只管理自己的会议，ADMIN可管理任意会议；普通用户不能取消别人的会议。该规则覆盖此前开放取消权限的说法。
- 使用北京时间。开始时间限未来滚动72小时，结束可超出预约窗口；不得预约过去，最短15分钟、15分钟步长，最长包含24小时，允许跨天。
- 同一房间有效会议不得重叠；相邻时段可连接，使用[start,end)。只能预约启用的房间。
- 发起人自动算一名参会者，人数由报名名单计算。容量为1～100，报名无需审批，满容量拒绝；用户可退出。踢人移除报名并禁止该账号再次加入该会议。
- 开始前发起人可改名称、说明、房间及时间；修改校验时间规则、容量及房间冲突。开始后仅可改名称、说明、踢人或提前结束。开始后停止报名。
- 提前结束立即释放剩余时段，到期自动结束。取消保留取消状态；删除物理清除会议及参会记录，释放时段，链接显示不存在。
- 删除尚有未结束会议的房间时拒绝，可先处理相关会议。设备使用固定选项多选。

## 账号与通知

- 用户名唯一，用户名+密码注册登录；不采集邮箱，不发邮件。不做忘记密码，用户忘记后重新注册。
- 关闭浏览器后保持登录30天，使用期间续期；主动退出清除并撤销登录。保留刷新Token机制。具体Token轮换与存储方案由认证设计明确，禁止明文存储密码。
- 接受站内通知及标记已读，RabbitMQ异步处理真实业务事件。用户后来明确不需要会议修改、取消、删除通知；报名、退出、踢人、结束的具体收件人及事件范围仍待最终确认。
- 最多五张核心业务表：账号、会议室、会议、参会记录、站内通知。技术表单独列明用途，不隐性增加核心业务表。

## 技术与界面

Java21、Spring Boot3.5.16、MyBatis-Plus3.5.17、MySQL8.4、Redis8.2、RabbitMQ4.3、Node24、Vue3.5、Vite8.1、TypeScript5.9、Element Plus2.14；Maven3.9.x Wrapper统一构建。补充Spring Security、JWT、Vue Router、Pinia、请求库、Vitest、vue-tsc、JaCoCo、Actuator及OpenAPI工具。测试依赖优先遵循Boot兼容管理，最终版本验证后锁定，冲突或缺版本报告后再决定，不静默换栈。

中文简洁企业风，桌面优先，手机基本可用。页面包括登录注册、会议室与空闲查询、会议列表及详情/分享报名、我的会议与参会、站内通知、管理后台。公开演示站点的功能须登录，不默认登录演示账号。

## 整体完成标准

1. 冻结首版需求和验收场景全部实现，API超过10个，核心表不超过五张。
2. 后端、前端可重复构建；必需单元、集成、E2E及安全检查通过，无阻断缺陷。关键业务单测分支覆盖率至少80%，不额外设置负载指标。
3. 验证时间边界、权限、报名容量、踢人、房间并发冲突、长期登录与撤销、MQ重复与失败恢复。
4. GitHub Actions实际跑通，GHCR保存可追溯镜像。一个功能切片一个分支一个PR，用户人工审查合并，合并后自动部署staging，production发布前用户确认。
5. staging、production隔离开发数据，核心流程上线验证通过；备份恢复及应用回滚验证，维护文档和最终交接齐全。
6. 部署前询问用户域名，域名后期可添加；当前不将HTTPS、邮件作为完成前提。未完成或未验证项如实记录。
